# Deploying Spoorthi Groups to Cloudflare Workers

The site is a Next.js 16 app running on Vinext (Vite) for Cloudflare Workers,
with a Cloudflare D1 database (`DB` binding) for enquiries. It no longer uses
ChatGPT Sites: admin sign-in is a password login (`/admin/login`, see README).

Do not buy the domain first — the site deploys first on a `*.workers.dev`
address, and the custom domain is added at the end.

## 1. Prerequisites

- A Cloudflare account (free tier is enough to start).
- Node.js 22.13 or newer, and this repo checked out.
- `wrangler` is already a devDependency; no global install is needed.

## 2. Log in to Cloudflare

```bash
npm install
npx wrangler login
```

## 3. Create the D1 database

```bash
npx wrangler d1 create spoorthi-groups
```

Copy the `database_id` from the output into `wrangler.jsonc`, replacing the
`00000000-0000-4000-8000-000000000000` placeholder. Then create the tables
(the app also creates them automatically on first use, so this step is
belt-and-braces):

```bash
npx wrangler d1 migrations apply spoorthi-groups --remote
```

## 4. Set the admin password (required)

Choose a strong password — it is the only way into `/admin`. It must never be
committed to git. Set it as a secret:

```bash
npx wrangler secret put ADMIN_PASSWORD
```

Optional, but recommended: a separate signing key for admin session cookies.
If you skip this, `ADMIN_PASSWORD` is used as the signing key instead
(changing the password then signs everyone out).

```bash
npx wrangler secret put ADMIN_SESSION_SECRET
```

## 5. Deploy

```bash
npx @vinext/cloudflare deploy
```

This builds the app (`vinext build`) and deploys it to Cloudflare Workers.
Your site will be live at `https://spoorthi-groups.<your-subdomain>.workers.dev`.

Verify it: open the homepage, submit a test enquiry, then sign in at
`/admin/login` with `spoorthigroups22@gmail.com` and the `ADMIN_PASSWORD` you
set, and check the enquiry is listed.

## 6. Add the custom domain (after buying it)

1. In the Cloudflare dashboard, open Workers & Pages → `spoorthi-groups` →
   Settings → Custom Domains → Add `spoorthigroups.in`.
2. Cloudflare will tell you what DNS to set. In Hostinger (where the domain
   was bought), point the domain at Cloudflare as instructed — usually by
   changing the domain's nameservers to Cloudflare's, or adding the CNAME
   record Cloudflare shows.
3. Wait for DNS to propagate (minutes to a few hours). SSL is automatic.
4. `NEXT_PUBLIC_SITE_URL` is already `https://spoorthigroups.in` in
   `wrangler.jsonc` and in `lib/config.ts`, so no code change is needed. If
   you deploy through Workers Builds, also set `NEXT_PUBLIC_SITE_URL` as a
   build variable there (the layout falls back to `lib/config.ts` if it is
   missing, so the site still works without it).

## Troubleshooting

- `Database binding unavailable` — the `DB` binding is missing: check the
  `database_id` in `wrangler.jsonc` matches the D1 database you created.
- Admin login always fails — `ADMIN_PASSWORD` is not set as a secret
  (`npx wrangler secret put ADMIN_PASSWORD`), or you are signing in with an
  email other than `spoorthigroups22@gmail.com`.
- `wrangler.jsonc` was regenerated by a deploy — re-check that the
  `d1_databases` entry for `DB` is still there before deploying again.
- `DB assigned to multiple D1 Database bindings` — the `DB` binding must be
  declared in exactly one place: `wrangler.jsonc`. Do not re-add it in
  `vite.config.ts`; that was the old Sites setup and it breaks deploys.
